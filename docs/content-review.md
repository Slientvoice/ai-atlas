# 内容核验方法与台账

2026-10-26 · v0.36。第一批覆盖入门旅程九站，以及蓝图中的分词、Embedding、注意力、FFN、Prefill / Decode、KV 缓存、采样、RAG、Agent、护栏十个模块的核心表述。

## 三种独立口径

- **建设**：页面、实验或草稿是否存在。原看板的加权完成度只表达这一口径。
- **来源核对（AI）**：AI 阅读一手论文、实现或官方文档，对照台账所列的具体表述并修订。它不表示整页、全部分支、全部历史参数或所有实验代码已经通过审计。
- **人工审校**：有姓名、日期、范围说明的人的复核记录。技术审校与法律审校分开记录；没有记录时保持待审校。

“教学简化”是实验的边界，与是否对照来源相互独立。真实函数运算不代表参数是真实模型权重，人工坐标或预写剧本也不代表实测结果。

本轮蓝图核心表述 10/45、入门核心表述 9/9；人工技术审校 0/54，索引合规挂点法律审校 0/28。分母分别对应模块、站点、索引挂点，不计算混合总分。蓝图与入门中的法律观察也仍待审校。谱系和工业现场保留各自快照与来源记录，不纳入这 54 个技术核验单元。

## 唯一记录位置

[`assets/content-review.json`](../assets/content-review.json) 保存单元、证据表述、来源、核对日期、教学边界、正文指纹与人工审校记录。来源记录区分“查阅日期”和原资料版本；旧论文用于原理，不据此推断当前市场格局。

每条 `evidence` 将一个表述对应到若干来源。`checkedAt` 为本次 AI 对照日期，`humanReview` 默认 `null`。`legalHooks[].review` 只在真实法律审校完成后填写姓名、日期和范围。网页上的计数、标记与链接由台账生成，避免手写多个百分比。

## 修改流程

1. 修改正文并阅读支持该表述的一手来源，确认适用条件、反例与教学简化。只检索到标题或打不开正文的来源，不作为本轮新核对证据。
2. 更新该单元的 `evidence`、`boundary` 与 `checkedAt`。未复核的改动应把 `checkedAt`、`method`、`contentHash` 设为 `null`，保留旧证据作为线索时也不计入已核对数。
3. 对确认后的单元，用 `scripts/content-review-lib.mjs` 的 `unitsIn` 读取对应 `content`，再用 `digest(content)` 记录 `contentHash`。不得只更新指纹以绕过核对。
4. 运行 `npm run sync:reviews`，随后 `npm run check:reviews`、`npm test`、`npm run typecheck`、`npm run build`、`npm run check:links`。
5. 检查页面展开、深链接、窄屏与无 JavaScript 时的核验说明；同步版本记录后发布。

构建检查会拒绝“正文已变但仍沿用旧核验指纹”的发布。指纹覆盖对应模块/站点的 HTML，排除自动生成的核验块；它不覆盖页外脚本，也不会自动感知外部资料更新。实验代码、时效性资料和法律适用仍需独立复核。技术稳定性较低或外部资料发生变化时，应主动把记录转回待复核。
