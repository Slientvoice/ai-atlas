SECTION 01 · OPENNESS & LICENSE STRATIFICATION

开放度阶梯 · 「开源」的六层真相与 2026“同厂双轨”浪潮

一个模型 = 权重 + 训练代码 + 数据。商业大模型无一公开训练数据，所谓「开源」几乎全指「开放权重」。而 2026 年下半年最大的法务剧变在于：过去把 L1 笼统归为“限制性许可”已不够细——开放权重已分化为「纯宽松（L2）」「商业/MaaS 营收闸门（L1-B）」与「地域排除 / 默认非商用 / 远程控制（L1-A）」三档，且几乎所有大厂都在实行“小模型宽松引流、万亿旗舰设商业闸门”的同厂双轨制。

L4 全开放权重 + 训练代码 + 数据

从零可复刻。商业公司至今无一做到——训练语料永不公开，恰恰是全行业最大的著作权与数据合规风险信号。

从「限 MaaS」升级到「封杀 AI 办公助手与第三方 Agent 框架」

典型条款：① Qwen3.8-Flash-Next（Qwen Community License 1.0）独树一帜，不仅限 MaaS，更直接将面向编码或办公效率的「AI Work Assistant」商业产品列为须另签授权类别（无营收豁免！）◉；② Mistral Large 4 无营收门槛一刀切限制第三方 MaaS◉；③ 闭源端围墙化：Anthropic 于 2026-03/04 封禁 Claude 订阅 OAuth 令牌接入第三方 Agent Harness，强推自家 Claude Code◉；OpenAI 于 2026-08 以合同违约为由切断 SpaceX 收购后的 Cursor 模型供应◐。

法务暗坑：创业公司与 SaaS 厂商常误以为“只要不做模型托管、只做垂直应用”就安全，却忽视了 Qwen 对“AI 办公/编码助手”的直接点名，以及闭源厂商随时可借“反转售/反第三方外壳”条款切断关键上游接口。

社区实务争议：HN 与 Reddit 开发者认为“模型厂商下场做第一方 Agent/IDE 后，与下游生态从合作转为直接竞争”，倒逼企业搭建多模型网关与可替换 Harness◐。

典型条款与禁令：① 许可证硬性地域排除：HunyuanVideo / 3D / HY-Motion 排除欧盟、英国、韩国；MiniMax H3 同时排除美、欧、英、韩；Llama 4 多模态排除欧盟境内主体◉；② 股权穿透封禁：Anthropic 禁止全球中资控股 >50% 实体及海外子公司使用 Claude◉；③ 公法制裁与供应链传导：美国 DHS 2026-10-20 FASCSA 排除令将 DeepSeek 及「使用其开发（developed using）」的系统逐出联邦民用系统与采购链；智谱（Z.ai）列美 BIS 实体清单与州禁令◉；④ 中国境内强制合规：面向公众服务须完成双备案与《标识办法》显隐式双轨标识。

法务暗坑：中资出海企业面临“用美系怕股权穿透断供 + 数据出境，用国产开源多模态怕欧美地域排除，涉美政府供应链怕 FASCSA 倒查合成数据”的三明治夹击。

社区实务争议：GitHub（如 Tencent HY-Motion #49）涌现大量欧洲开发者抗议“标注开源却在欧盟零授权”，业界解读排除欧英韩系厂商为规避 2026-08 生效的 EU AI Act 生成媒体透明度与版权合规义务◐。
雷区 04 · 数据训练 / 强制留存 / 平台锁定

免费层“数据付费”、司法保全打破删除承诺与微调资产被锁死

典型条款：① 免费/消费层默认训练：Google Gemini 免费 API 默认训练且允许人工审阅；Anthropic 消费版默认训练且留存 5 年；Mistral 免费 Experiment 层默认训练；DeepSeek 隐私政策默认训练（提供 opt-out）且 API 条款未写留存期与 DPA◉；② 有状态接口与司法保全：OpenAI Responses API 默认 store: true 存 30 天，且 NYT 诉案法院曾令无限期保全已删对话◉；③ 微调权属剥离与锁定：火山方舟 §3.7.14 规定客户不得主张精调模型 IP 且仅限部署于火山引擎；§3.7.17 允许提前 15 天单方下架免责◉；④ 远程控制权：旧版 Gemma Terms of Use 赋予 Google 远程限制使用权◉。

社区实务争议：Reddit r/ChatGPT 与 r/ClaudeAI 长期批评“宣称 30 天删除却因诉讼或政策改口变 5 年/无限期留存”，促使受监管行业加速转向 ZDR 或私有化部署◐。
雷区 05 · IP 赔偿盾空洞与通道断档

「有赔偿盾 ≠ 赔得到」：修改失保、三方云真空与国产反向赔偿

典型条款：① 免责空洞极窄：OpenAI Copyright Shield 排除修改输出、未启用官方过滤/引用工具及商标侵权；Google 双重赔偿盾限于付费 GA 服务的“未修改输出（unmodified）”；Anthropic 虽覆盖训练与输出，但普通商用协议责任上限仅 6 个月费用或 $100，且自身背负 $15 亿书籍和解与 $31 亿音乐诉讼引发赔付能力讨论◉；② 调用通道断档：OpenAI 协议排斥第三方受益人（经聚合网关/转售商失保）；AWS Bedrock / Google Vertex AI 上调用第三方模型，云商通常对第三方模型免责（如 Google §19(b)）◉；③ 国产云/API 反向赔偿：火山方舟、阿里云百炼等标准条款均无正向 IP 赔偿盾，反要求客户就输出侵权自行担责并赔偿平台损失◉。

法务暗坑：采购部门在清单里打勾“供应商有 IP 赔偿”，但在真实工作流中员工几乎一定会编辑 AI 稿件或通过路由网关调用，导致真正出事时赔偿条款形同虚设。

社区实务争议：欧美法务评论（Beri.net / ComputeLaw 等）指出 2026 年企业 AI 合同谈判焦点已从“有没有盾”转向“修改后输出、微调模型、多云路由与赔偿上限豁免”四大细则◐。
雷区 06 · 反蒸馏 / 输出衍生传染 / 静默中转风险

从合同违约升级为国安警告与客户数据二次外泄危机

典型条款与事件：① 闭源 ToS 全面反蒸馏：OpenAI、Anthropic、Google、SpaceXSI、火山方舟等均严禁利用输出训练/蒸馏竞品模型◉；② 开源许可反向传染：Meta Muse Model License 明确将“基于模型输出蒸馏的新模型”界定为衍生品并强制继承署名与限制；HunyuanVideo / 3D 与 Grok 2.5 禁止用输出训练其他 AI 模型◉；③ 2026-09 蒸馏与中转风暴：美 CISA/NSA/FBI 联合警告点名 6 家中国模型商，随后 Anthropic 发布报告指控阿里、月之暗面、DeepSeek 等通过代理账号大规模提取推理链，并称部分厂商疑似将自身真实客户请求静默转发给 Claude（中方商务部强烈反驳美方将技术商业问题政治化）◐。

法务暗坑：① 企业内部若用闭源旗舰生成合成数据去微调自有小模型，直接构成 ToS 违约与不正当竞争风险；② 调用不明来源的低价“套壳/聚合 API 中转站”，可能发生商密与个人数据被不知情跨境转发甚至截留用于训练的双重泄密。

社区实务争议：法律界普遍指出单纯版权法难以封堵蒸馏，但伪造账号/规避风控触发违约与 CFAA 风险；企业更警惕的是“模型商或中转站悄悄把我的 prompt 转发给了另一家境外厂商”◐。

SECTION 04 · LEGAL COMPLIANCE ARCHITECTURE & CHECKLIST

⚖ 法务合规视角：模型选型页应补齐的六大治理维度与上线快检

对照谱系 v2（偏重技术架构 + 四条原则性朱批），从企业法务与合规实务出发，模型选型决策必须补齐以下六项结构性治理条目——因为技术跑分只决定「好不好用」，这六项决定「能不能上线、签不签得下、出事谁赔钱」。

ADD-01 · MODEL REGISTER / AI BOM

1. 版本级许可证台账（而非厂商名）

建立精确到 模型 ID + 仓库 Commit + 下载当日 LICENSE 原文存档 的台账，并标注是否存在营收/MAU 动态门槛与复核周期。杜绝把 Hy4-preview（Apache 2.0）当成 Hy4 正式版（Sec.10），或把 Qwen3.8-27B 的评估结论套用到 Flash-Next。

ADD-02 · ROUTE-OF-PURCHASE MATRIX

2. 调用路径决定法律后果（六路径映射）

同一款模型，换一条调用路径，数据训练、跨境法域、DPA 与 IP 赔偿盾全部改写：① 消费版/免费 API（默认训练/人工审阅，严禁商密）→ ② 厂商直连商用 API（看 ZDR 与赔偿盾细则）→ ③ 一线云商托管闭源模型（Azure/Bedrock/Vertex/百炼/方舟，查三方模型免责与精调锁定）→ ④ 聚合中转站/路由网关（极易断保且存在二次转包泄密风险）→ ⑤ 第三方合规云托管开放权重（受 MaaS 营收闸门与云商 DPA 双重约束）→ ⑥ 本地/私云自托管开放权重（数据主权最高，重心转向权重许可证、安全评估与双备案）。

ADD-03 · ENTITY & SANCTIONS SCREENING

3. 主体股权穿透、制裁与双备案映射

把选型页的「辖区」一栏升级为双向准入审查：对内查中国网信双备案、TC260 语料与拒答达标及《标识办法》显隐式双轨标识；对外查股权穿透（Anthropic 中资控股 >50% 禁令）、BIS 实体清单（智谱）、DHS FASCSA「developed using」供应链传导（DeepSeek）及 EU AI Act 地域排除（混元视频/3D、MiniMax H3、Llama 4 多模态）。

ADD-04 · DATA LIFECYCLE & LITIGATION HOLD

4. 数据流、工具出圈与「司法保全冲突」

不再只问“是否拿我数据训练”，须追问四层细节：① 默认日志留存期与有状态接口开关（如 store: false）；② 内置联网搜索、代码沙箱、MCP 工具是否把数据带出受控边界；③ 供应商涉版权诉讼被法院下令强制保全用户已删日志时（NYT v. OpenAI 先例）是否受 ZDR 豁免；④ 终止合作后“匿名化继续留存”条款边界。

ADD-05 · COMMERCIAL EXIT & FALLBACK

5. 商业可持续性、微调权属与兜底预案

合同谈判必锁四点：① 微调权重/LoRA 资产权属与可迁移性（防火山方舟 §3.7.14 式锁定）；② 模型下架通知期（15 天远不足生产迁移，争取 90 天+）；③ 长协价格随官网刊例价下调的联动机制（MFN/阶梯调价）；④ 技术栈内常备至少一个纯 Apache 2.0 / MIT 兜底模型（如 DeepSeek V4、Gemma 4、Qwen3.8-27B、Mistral Small 4），防突然断供或触发营收红线。

ADD-06 · HIGH-RISK TIER & AGENT LIABILITY

6. 高危网安档位与 Agent 越权归责

2026 年底前沿模型已普遍分化出受限网安变体（Claude Mythos / GPT-6 Cyber / Gemini 3.8 Flash Cyber），且 Google Cloud 等已将客户反向赔偿扩展至 AI Agent 违规行为。引入自主 Agent 与计算机操控能力时，必须在权限沙箱、人工确认点（HITL）与操作审计日志层面提前留痕（回看 蓝图 Ⅳ·Agent）。
