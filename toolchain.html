ST.00地基与内核

蓝图 PLANE 0 讲了 GPU 为什么快、内存墙卡在哪；工地上这一层的通用语言是 CUDA——以及绕开手写 CUDA 的新路。

CUDAGPU 编程平台◐

NVIDIA 的 GPU 编程语言与运行时——想让 GPU 干活，最终都要有人把计算写成它认识的样子。

为什么绕不开：十几年生态积累是 NVIDIA 最深的护城河：框架、算子库、驱动全绑在它身上。「买不到卡就寸步难行」说的一半是硬件，另一半就是它。

原理在蓝图：0 · 为什么是 GPU · 0 · 屋顶线模型

Triton内核语言◐

OpenAI 开源的「用 Python 写 GPU 内核」语言；PyTorch 2 的编译器 torch.compile 就用它生成算子。

为什么重要：把写高性能内核的门槛从「CUDA 专家」降到「熟练 Python」，也是打破 CUDA 独占的关键一环。FlashAttention 这类手工内核正是它的用武之地。

原理在蓝图：0 · 为什么是 GPU · Ⅱ · 注意力

NCCL通信库◐

多卡多机之间同步梯度与激活的通信库——蓝图「互联与集群」讲的 AllReduce，工程上就是调它。

为什么重要：千卡训练的神经系统；它一卡顿，整个集群一起等（这就是互联带宽写进屋顶线的原因）。

原理在蓝图：0 · 互联与集群

ST.01训练车间

对应蓝图 Ⅰ 训练管线 整条传送带。PyTorch 是全部上层建筑的地板；预训练靠并行框架把模型切上千卡；后训练（SFT / 偏好优化 / RLVR）有自己的一套家伙什。

PyTorch深度学习框架◉

定义模型、自动求导、驱动 GPU 的基础框架——你在「迷你训练场」里手写的反向传播，它帮业界自动做。

地位：研究与工业的双料默认；Llama、Qwen、DeepSeek 的训练代码都建在它上面（TensorFlow 时代已经过去 ◐）。

原理在蓝图：Ⅰ · 预训练循环 · Ⅱ · Block 总装

Megatron-LM + DeepSpeed千卡并行◐

把一个装不进单卡的模型切开训练：Megatron-LM（NVIDIA）管张量/流水并行的「切法」，DeepSpeed（微软）的 ZeRO 管显存的「省法」，PyTorch 原生的 FSDP 是后起的官方选项。

为什么重要：蓝图「互联与集群」讲的 3D 并行不是纸上概念，工程上就是这几家的组合拳。

原理在蓝图：0 · 互联与集群 · Ⅰ · 预训练循环

TRL后训练库◉

Hugging Face 的后训练全家桶：SFT、DPO、PPO、GRPO 一个库全有——业界公认的教科书式参考实现。

为什么重要：你在蓝图学过的 SFT 损失掩码、偏好优化、可验证奖励，它每一样都有开箱即用的 Trainer。

原理在蓝图：Ⅰ · 监督微调 SFT · Ⅰ · 可验证奖励

verlRL 训练框架◉

字节跳动开源的大规模 RL 后训练框架（HybridFlow 论文的开源版）——RLVR 时代训推理模型的主力装备之一，同赛道还有 OpenRLHF。

为什么重要：RL 训练要同时伺候「生成」（推理引擎）和「更新」（训练框架）两套系统，verl 的本事是把两者高效缝合——rollout 常直接挂 vLLM/SGLang，训练与推理两张版图在这里握手。

原理在蓝图：Ⅰ · 可验证奖励与推理训练

LLaMA-Factory微调工作台◉

一站式微调台：选模型、选方法（LoRA / SFT / DPO…）、点运行——把后训练做成了带界面的流水线。

为什么重要：中文社区的入门首选；很多「我微调了一个自己的模型」的故事从这里开始。

原理在蓝图：Ⅰ · 监督微调 SFT

ST.02权重集散地

蓝图里「权重冻结」之后，模型变成一个文件。这一站讲文件住在哪、什么格式、怎么分发——开放权重生态的物流系统。

Hugging Face Hub模型集散地◉

「模型的 GitHub」：权重、数据集、在线演示都托管在上面，是开放权重生态的地基。

为什么重要：谱系页讲的开放度阶梯，物流环节全在这里发生——一个模型「开放」与否，最终体现为它在 Hub 上放出了什么。

原理在蓝图：Ⅱ · 模型本体 · 延伸：🧬 谱系 · 开放度阶梯

Transformers模型加载库◉

Hugging Face 的标准库：Hub 上任何模型都按同一套接口加载、推理、微调——from_pretrained 一行搞定。

为什么重要：「换模型不换代码」的抽象层。模型架构千变万化，接口只有一个。

原理在蓝图：Ⅱ · Block 总装

safetensors & GGUF权重文件格式◐

权重的两大文件格式：safetensors（HF 标准，只存数字不藏代码——取代了能夹带恶意代码的 pickle）；GGUF（llama.cpp 生态的格式，一个文件塞下整个量化模型）。

为什么重要：格式即生态门票——发权重必发 safetensors，进端侧必转 GGUF。附一个安全侧写：pickle 反序列化漏洞曾是模型供应链的真实攻击面。

原理在蓝图：Ⅲ · 量化

ModelScope 魔搭国内集散地◐

阿里的模型社区：国内访问 Hugging Face 不稳时的主镜像与首发地，Qwen 系全量在此。

为什么重要：网络与合规双重原因，国内工程实践常以它为默认源。

延伸阅读：🧬 谱系 · 国内梯队

ST.03推理机房

对应蓝图 Ⅲ 推理服务。你学过 KV Cache、连续批处理、投机解码、量化——这里的每台引擎，就是同一批概念的不同打包方式。

vLLM推理引擎◉

生产级推理引擎的事实标准。它带给全行业两件礼物：PagedAttention（把 KV Cache 当虚拟内存分页管理）和连续批处理。

地位（2026-07 核实）：硬件支持最广、社区最大；Hugging Face 自家的 TGI 已进维护模式，其推理端点默认改用 vLLM。通用负载选它不会错。

原理在蓝图：Ⅲ · KV 缓存 · Ⅲ · Prefill / Decode

SGLang推理引擎◉

与 vLLM 并驾的另一台发动机：RadixAttention 把多请求间的公共前缀（系统提示词、多轮历史）自动复用，结构化输出（强制 JSON 等）也做得深。

地位（2026-07 核实）：多轮对话、Agent 循环、RAG 这类「前缀重复率高」的负载上常反超 vLLM——你在论坛看到它，多半就是这些场景；DeepSeek 等模型发布时官方适配。同赛道还有量化见长的 LMDeploy。

原理在蓝图：Ⅲ · KV 缓存 · Ⅳ · 上下文拼装 · Ⅲ · 采样

TensorRT-LLM推理引擎◐

NVIDIA 亲儿子：把模型编译成榨干自家 GPU 的推理引擎，延迟与吞吐常是天花板。

取舍：上限最高、门槛也最高——换模型要重编译，是「灵活性换性能」的极端选项。

原理在蓝图：Ⅲ · 量化 · 0 · 为什么是 GPU

llama.cpp端侧推理◉

传奇个人开源项目（Georgi Gerganov 发起）：纯 C/C++ 实现，让大模型跑在笔记本、手机甚至树莓派上；GGUF 格式的老家。

为什么重要：「推理不一定要机房」的证明，整个本地模型生态的地基。

原理在蓝图：Ⅲ · 量化

Ollama本地运行器◉

给 llama.cpp 套上极简外壳：ollama run qwen3 一条命令，在自己电脑跑开放权重模型。

为什么重要：本地跑模型的第一入口；隐私敏感的场景（比如法务文档）想「不出本机」过一遍模型，这是最低门槛的方案。图形界面档还有 LM Studio。

原理在蓝图：Ⅲ · 量化 · 延伸：🧬 谱系 · 开放度阶梯

ST.04组装车间

对应蓝图 Ⅳ 系统组装。Agent 循环、RAG、工具协议在蓝图里是概念；工地上，它们叫 LangGraph、LlamaIndex、MCP。

LangChain / LangGraphAgent 编排◉

LangChain 是最早的「LLM 应用乐高」；如今重心已移到 LangGraph——把 Agent 工作流写成显式状态机（图），每一步可查、可控、可回放。

地位（2026-07 核实）：有状态生产工作流的默认选项，受监管行业尤其偏爱它「每一步都留痕」的性格——这一点你作为法务应该会心一笑。

原理在蓝图：Ⅳ · 多智能体编排 · Ⅳ · 工具与 Agent

MCP工具协议◉

不是库，是协议——你已在蓝图「工具协议」模块学过它的报文。2024-11 由 Anthropic 发布，十八个月内 OpenAI、微软、谷歌、亚马逊全部接入；OpenAI 甚至弃用了自家 Assistants API 转向 MCP 路线。

为什么重要：「工具接入从 N×M 变 N+M」从提案变成了业界公约数；各家 Agent SDK（Claude Agent SDK、OpenAI Agents SDK 等）原生支持。

原理在蓝图：Ⅳ · 工具协议（含报文显微镜实验室）

LlamaIndexRAG 框架◉

RAG 起家的框架：文档解析、切分、索引、检索问答，这条链的纵深业界最深。

为什么重要：你在 RAG 实验室亲手做过的切分与检索，它是工业化版本——「文档问答为主、Agent 为辅」的应用首选。

原理在蓝图：Ⅳ · RAG

Dify低代码平台◐

开源低代码 LLM 应用平台：拖拽画布搭 RAG 机器人和工作流，不写代码就能上线。

为什么重要：「会用 ≠ 会写」的中间地带，国内企业内部工具的常见底座；同赛道还有字节的扣子（Coze）。

原理在蓝图：Ⅳ · 工具与 Agent

Langfuse / LangSmith可观测性◐

Agent 的行车记录仪：记录每次调用的完整轨迹——提示词、工具调用、token 数、延迟、成本，出错能回放。

为什么重要：蓝图讲过多智能体的「协作税」；不装记录仪，生产系统里的错误根本无从归因。

原理在蓝图：Ⅳ · 多智能体编排（编排剧场实验室的「日志」就是它的雏形）

ST.QC质检站

对应蓝图 Ⅰ · 评估·红队·发布。跑分、盲测、训练心电图——模型出厂前后的一切体检。

lm-evaluation-harness & OpenCompass跑分器◐

自动评测的两大标准框架：lm-evaluation-harness（EleutherAI，学界通行）与 OpenCompass（上海 AI 实验室，国内体系）——几百个基准一键跑。

清醒剂：蓝图「评估·红队」讲过基准的局限——工具再顺手，数据污染与刷榜的坑还在（回看污染检测器实验室）。

原理在蓝图：Ⅰ · 评估·红队·发布

Weights & Biases训练监控◐

炼丹师的心电图：损失曲线、梯度、显存实时上报到仪表盘，训练跑飞了第一时间看见。

为什么重要：蓝图预训练循环里那条「损失下降曲线」，工业界就是在它上面盯的；一次千卡训练几百万美元，盯梢就是省钱。

原理在蓝图：Ⅰ · 预训练循环

LMArena人类盲测◐

两个匿名模型同题竞答、人类投票选优的天梯榜（原 Chatbot Arena）——Elo 分是业界最难刷的榜。

清醒剂：自动基准会被污染，人类盲测难作弊——但有偏好偏差：投票者偏爱长答案和漂亮格式，你在 RLHF 标注间见过这个毛病的训练版。

原理在蓝图：Ⅰ · 评估·红队·发布

ST.DEV你手边的工具

不在模型生产线上，但在每个技术人员的手边——本站本身，就是用这一格里的工具建成的。

Git & GitHub版本管理◉

代码的版本台账与协作广场：每次改动可追溯、可回滚、可署名——你已经在用（本站两个仓库就住在上面）。

为什么放在这：它是技术世界的公证处，也是一切开源工具的分发地。台账、留痕、可回滚——对法务来说这套逻辑毫不陌生。

实践现场：本站私有档案仓 + 公开站点仓的双仓流水线

Claude Code / Cursor / CopilotAI 结对编程◉

终端或编辑器里的 AI 工程师：读整个仓库、改代码、跑命令、修测试——本质是一个装上了工具协议的 Agent 循环。

为什么放在这：本站 45 个实验室全部由这种方式结对建成——你此刻就站在这条生产线上，而且是甲方。
